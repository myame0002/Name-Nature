# iNaturalist API の代替案

## 概要

iNaturalist APIの長期トークン取得が困難な場合、別のAI識別サービスを検討できます。本ドキュメントでは、主要な代替案を比較します。

## 主要な代替サービス

### 1. **Plant.id API** 🌿
**特徴**: 植物識別に特化したAPI

- **公式サイト**: https://plant.id/
- **料金**: 無料枠あり（1日100リクエスト）、有料プランあり
- **精度**: 植物に特化しており、高い識別精度
- **利点**:
  - 植物識別に最適化
  - シンプルなAPI
  - 無料で始められる
- **欠点**:
  - 植物のみ（キノコ、鳥、昆虫には非対応）
  - 日本語対応が限定的

### 2. **Pl@ntNet API** 🌱
**特徴**: オープンソースの植物識別プロジェクト

- **公式サイト**: https://my.plantnet.org/
- **料金**: 無料（オープンソース）
- **精度**: 高い（研究用途にも使用）
- **利点**:
  - 完全無料
  - 植物識別に特化
  - コミュニティ主導
- **欠点**:
  - 植物のみ対応
  - APIの利用に制限がある場合あり
  - ドキュメントが限定的

### 3. **Google Cloud Vision AI** 🔍
**特徴**: 汎用的な画像認識API

- **公式サイト**: https://cloud.google.com/vision
- **料金**: 無料枠あり（月1,000リクエスト）、従量課金
- **精度**: ラベル検出は高いが、特定種の識別は限定的
- **利点**:
  - 高い信頼性
  - 多様な認識機能（ラベル、ランドマーク、顔など）
  - スケーラブル
- **欠点**:
  - 植物/動物の特定種識別には不向き
  - 詳細な分類情報が得られない
  - 有料（従量課金）

### 4. **Microsoft Azure Computer Vision** 👁️
**特徴**: Microsoftの画像認識サービス

- **公式サイト**: https://azure.microsoft.com/services/cognitive-services/computer-vision/
- **料金**: 無料枠あり（月5,000トランザクション）
- **精度**: ラベル検出は良好
- **利点**:
  - 無料枠が大きい
  - 多機能
  - ドキュメントが充実
- **欠点**:
  - 特定種の識別には不向き
  - 植物/動物特化ではない

### 5. **iNaturalist API（現状）** 🦎
**特徴**: 生物識別に特化

- **料金**: 無料
- **精度**: 非常に高い（生物特化）
- **利点**:
  - 生物識別に最適化
  - 詳細な分類学的情報
  - コミュニティデータに基づく
- **欠点**:
  - 長期トークン取得にハードル（アプリ所有者申請が必要）
  - 短期トークンは2日で無効

## 推奨されるアプローチ

### オプションA: Plant.id + Pl@ntNet の組み合わせ（植物特化）

**対象**: 花のみの識別

**実装**:
1. Plant.id APIをメインに使用
2. 無料枠で運用
3. キノコ、鳥、昆虫は手動入力に変更

**メリット**:
- 完全無料
- 植物識別の精度が高い
- 長期トークンの問題なし

**デメリット**:
- カテゴリが花のみに縮小
- API連携の実装が必要

### オプションB: 複数APIの併用

**対象**: 全カテゴリ（花、キノコ、鳥、昆虫）

**実装**:
1. 花: Plant.id
2. キノコ: 手動入力またはPl@ntNet（一部対応）
3. 鳥: 手動入力
4. 昆虫: 手動入力

**メリット**:
- 一部カテゴリでAI識別を維持
- コスト削減

**デメリット**:
- 複雑な実装
- ユーザー体験の低下

### オプションC: 短期トークンの自動更新スクリプト

**対象**: 全カテゴリ（現状維持）

**実装**:
1. 2日ごとに自動的にトークンを再取得するスクリプト
2. Cloudflare WorkersのCron Triggerで定期実行
3. トークン更新ロジックを実装

**メリット**:
- iNaturalist APIの高い識別精度を維持
- 自動化により運用負荷軽減

**デメリット**:
- 2日ごとの更新処理が必要
- 短期トークンの取得方法を確立する必要あり
- 依然としてiNaturalistの制約を受ける

### オプションD: 手動入力方式への移行

**対象**: 全カテゴリ

**実装**:
1. AI識別機能を廃止
2. ユーザーが手動で種名を入力
3. 図鑑機能のみを残す

**メリット**:
- API依存なし
- シンプルな実装
- 運用コストゼロ

**デメリット**:
- ユーザーに種知識が必要
- アプリの価値が大幅に低下
- ユーザー離れのリスク

## 推奨事項

### 短期的（1-2週間）
**オプションC（短期トークンの自動更新）** を検討:

**なぜ「短期的」か？**
1. **即座に実装可能**: 既存のiNaturalist APIを使い続けられる
2. **最小限の変更**: 自動更新スクリプトを追加するだけで済む
3. **精度を維持**: 現在の高い識別精度を保てる
4. **しかし根本解決ではない**: 
   - 2日ごとの更新処理が必要
   - iNaturalistの制約（短期トークン）から解放されない
   - 将来的に別の解決策が必要

**実装の簡単さ**: ★★★（中程度）
**持続可能性**: ★★（低い）
**識別精度**: ★★★（高い）

### 中期的（1-2ヶ月）
**オプションA（Plant.id）** を並行開発:
- 植物識別を無料で運用
- キノコ、鳥、昆虫は手動入力

**実装の簡単さ**: ★★（やや複雑）
**持続可能性**: ★★★（高い）
**識別精度**: ★★★（高い、植物のみ）

### 長期的（3ヶ月以上）
**オプションA+B** の統合:
- 複数の無料APIを組み合わせ
- または、アプリ所有者申請を再挑戦

**実装の簡単さ**: ★（複雑）
**持続可能性**: ★★★（非常に高い）
**識別精度**: ★★★（高い）
