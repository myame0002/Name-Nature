# 短期トークンの自動更新について

## ユーザーの提案の検討

「毎日0:00に短期トークンを自動更新すれば永遠に使えるのでは？」という提案について、技術的に可能かどうかを検討します。

## 結論から言うと

**残念ながら、このアプローチには根本的な問題があります。**

## 問題点

### 1. **短期トークンの取得自体にアプリ所有者承認が必要**

短期トークンであっても、取得するには：
- iNaturalistアプリケーションの登録
- アプリ所有者としての承認

**が必要です。**

つまり、短期トークンの自動更新スクリプトを作る**前**に、既にアプリ所有者として承認されている必要があります。

### 2. **短期トークンの仕様**

iNaturalistの短期トークン：
- 有効期限: 約2日（48時間）
- リフレッシュトークン: なし（または非常に短い）
- 取得方法: OAuth 2.0認証フロー

**重要な点**: 短期トークンには通常、リフレッシュトークンが付与されません。そのため、自動更新には毎回OAuth認証フローを実行する必要があります。

### 3. **OAuth認証フローの自動化の問題**

OAuth 2.0の認証コードフロー（Authorization Code Flow）：
1. ユーザーがブラウザで認証
2. 認証コードを取得
3. トークンと交換

**問題**: ステップ1と2は**人間の操作**が必要です。完全に自動化できません。

## なぜ「短期トークン」なのか？

iNaturalistが短期トークンを提供する理由：
- **セキュリティ**: 長期間有効なトークンは漏洩した場合のリスクが高い
- **制御**: トークンの使用を制限し、APIの乱用を防ぐ
- **監査**: 定期的な再認証により、利用状況を把握

## 可能なアプローチ（理論上）

### アプローチA: リフレッシュトークンを使用（確認が必要）

もしiNaturalistがリフレッシュトークンを提供している場合：
1. 初回認証時にリフレッシュトークンを取得
2. リフレッシュトークンを使ってアクセストークンを更新
3. Cloudflare WorkersのCron Triggerで定期実行

**確認が必要なこと**:
- iNaturalistがリフレッシュトークンを提供するか
- リフレッシュトークンの有効期限

### アプローチB: 手動更新の自動化（限定的）

人間が関与する部分を最小限に：
1. 管理者が手動で認証コードを取得（月1回程度）
2. スクリプトが自動的にトークンを更新
3. Cloudflare Workersに設定

**依然として人間の操作が必要**:
- 毎月1回、認証コードを取得する必要あり
- 完全自動化ではない

## 現実的な解決策

### 1. **アプリ所有者申請を再考**

やはりこれが最も確実：
- 2ヶ月以上経過（あなたはOK）
- 改善ID10個（今月中に追加可能）
- 承認後、長期トークンを取得

### 2. **複数のAPIを組み合わせる**

- Plant.id（植物、無料）
- その他は手動入力
- API依存を減らす

### 3. **現在の運用を続ける**

- 2日ごとに手動でトークンを更新
- アラート機能で通知
- 最もシンプル

## まとめ

**残念ながら、「毎日自動更新すれば永遠に使える」という単純な解決策はありません。**

理由：
1. 短期トークンの取得にアプリ所有者承認が必要
2. OAuthフローには人間の操作が必要
3. リフレッシュトークンの有無が不明

**推奨される道筋**:
1. 今月（6月）に改善IDを10個追加
2. 7月にアプリ所有者申請
3. 承認後、長期トークンを取得
4. 約1年間、メンテナンスフリーで運用

これが最も確実で長期的な解決策です。
